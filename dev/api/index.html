OptimizationVariableInterface — Module
OptimizationVariableInterface

The contract between the variables of an optimization problem and the optimizer that updates them. An optimizer computes a step in the tangent space of the variables, a flat vector of length nvars, and asks the variables to apply it (a retraction), without knowing what they are: scalars, static or dynamic vectors, bounded parameters, points on a manifold, or collections of differently typed blocks of these.

A variable type implements:

  • nvars: the number of degrees of freedom (a StaticInt when it is fixed by the type);
  • update: the out-of-place retraction along a slice of the step.

A type that is updated in place implements, in addition, update!, copyvars, syncvars! and ismutablevar. The trait iseliminable is optional.

source

The variable contract

Every variable type implements these; see Defining a variable type.

OptimizationVariableInterface.nvars — Function
nvars(v) -> StaticInt or Int

Returns the intrinsic number of degrees of freedom (tangent-space dimension) of a variable or collection of variables.

A number has static(1), and a StaticVector of numbers static(N). For a StaticVector, Vector, Tuple or NamedTuple of variable blocks, returns the sum over the blocks: a StaticInt when every block's count is static and the container is static (StaticVector, Tuple, NamedTuple), otherwise an Int.

Fallback: nvars(x) = length(x), used for any type without its own method (generic arrays, and custom types that define Base.length).

A custom type defines nvars(::MyType), unless the fallback is right for it. Return a StaticInt (static(N)) when the count is fixed by the type, so that an optimizer can size its linear system at compile time.

Example

julia> nvars(1.0)
static(1)

julia> nvars(@SVector [1.0, 2.0, 3.0])
static(3)

julia> nvars(zeros(5))
5

julia> nvars(SVector(ZeroToInfScalar(1.0), ZeroToInfScalar(2.0)))
static(2)

julia> nvars((1.0, SVector(1.0, 2.0)))
static(3)

OptimizationVariableInterface.update — Function
update(var, step, start=1) -> newvar

Computes the out-of-place retraction of var along the tangent vector step[start:start+nvars(var)-1], and returns the new variable; var is not changed. step is the optimizer's whole step vector, and start is the index of var's first element in it, so that no slice is allocated.

For a StaticVector, Tuple or NamedTuple of variable blocks, updates each block from its own slice of step, in order, and returns a container of the same kind; for a StaticVector this is unrolled and does not allocate.

Fallback: update(var, step, start=1) = var + @inbounds(view(step, start:start+nvars(var)-1)), used for any type without its own method. It is correct for a type whose retraction is addition and that defines Base.:+(::MyType, ::AbstractVector) (and Base.length, or nvars).

A custom type whose retraction is not addition defines update(var::MyType, step, start=1), reading only step[start:start+nvars(var)-1].

Example

julia> update(@SVector([1.0, 2.0]), @SVector([0.1, -0.1]))
2-element SVector{2, Float64} with indices SOneTo(2):
 1.1
 1.9

julia> update(1.0, [10.0, 0.5], 2)   # the slice starting at index 2
1.5
source
OptimizationVariableInterface.update! — Function
update!(to, from, step::AbstractVector) -> to

Updates variable state to from from along the tangent step step (starting at step[1]), writing into to where it can. For a Vector{<:Number}, or a Vector of variable blocks (each element replaced by update of the corresponding element of from), mutates to in place and returns to.

Always use the return value, as to = update!(to, from, step): for an immutable variable to cannot be changed, and the result is returned instead.

Fallback: update!(to, from, step) = update(from, step), used for any type without its own method: to is ignored and the new value is returned. This is correct for every out-of-place type.

A custom type that is updated in place defines update!(to::MyType, from::MyType, step::AbstractVector), writing the result into to and returning to, and must then also define copyvars, syncvars! and ismutablevar.

Example

julia> to = [0.0, 0.0];

julia> update!(to, [1.0, 2.0], [0.5, 0.5]) === to   # written in place
true

julia> to
2-element Vector{Float64}:
 1.5
 2.5

julia> x = update!(1.0, 2.0, [0.5])   # immutable: only the returned value is updated
2.5

In-place support

Needed only by a type that is updated in place; see In-place variable types.

OptimizationVariableInterface.copyvars — Function
copyvars(vars)

Returns a copy of vars suitable as a scratch buffer:

  • For immutable variables, returns vars itself (0 allocations).
  • For a mutable AbstractArray (e.g. Matrix, MVector), returns copy(vars).
  • For a Vector{T}, uses shallow copy(vars) when isbitsvartype(T) is true; otherwise copies each element with copyvars (so the policy is per-element and consistent with syncvars!).
  • For a Tuple or NamedTuple of variables, copies each element with copyvars.

Fallback: copyvars(x) = x, used for any type without its own method: the type is treated as an immutable value.

A custom type with an in-place update! (one that is mutable and not an AbstractArray) must define copyvars, returning an independent copy, and also syncvars!: the fallbacks treat unknown types as immutable values, which is only correct when update! is out-of-place. Such a type must also define ismutablevar(::Type{<:MyType}) = true (see ismutablevar), so that ismutablevar(x) == (syncvars!(x, y) === x) holds.

Example

julia> x = [1.0, 2.0]; copyvars(x) !== x   # a new buffer
true

julia> s = SVector(1.0, 2.0); copyvars(s) === s   # a value: nothing to copy
true
source
OptimizationVariableInterface.syncvars! — Function
syncvars!(to, from) -> to

Synchronizes the variable buffer to with from, so that afterwards the result holds from's values. For a mutable array, copies from into to and returns to; for a Vector of non-isbits variables, each element is synced with syncvars! (per element, as copyvars copies them). For a Tuple or NamedTuple, returns the tuple of per-element results. For an immutable variable, returns from.

Always use the return value, as to = syncvars!(to, from): only when ismutablevar(to) is to itself updated.

Fallback: syncvars!(to, from) = from, used for any type without its own method: the type is treated as an immutable value.

A custom type with an in-place update! must define syncvars!(to::MyType, from::MyType), copying from's state into to and returning to, as well as copyvars and ismutablevar.

Example

julia> to = [0.0, 0.0]; syncvars!(to, [1.0, 2.0]) === to
true

julia> to
2-element Vector{Float64}:
 1.0
 2.0

julia> x = syncvars!(SVector(0.0), SVector(1.0))   # immutable: only the returned value is synced
1-element SVector{1, Float64} with indices SOneTo(1):
 1.0
source
OptimizationVariableInterface.ismutablevar — Function
ismutablevar(x) -> Bool
ismutablevar(::Type{T}) -> Bool

Whether a variable (or container of variables) of this type is updated in place: that is, whether syncvars!(x, y) writes y's values into x and returns x itself, so that the caller's x holds the result. When it is false, x is treated as an immutable value: copyvars(x) returns x, and syncvars!(x, y) returns y.

This is not Base.ismutable. A tuple of mutable arrays is updated in place although a tuple is immutable; a mutable struct that has not opted in is not.

The defining property: for y of the same type as x but with different contents, let r = syncvars!(x, y). If ismutablevar(x), then afterwards the caller's x itself holds y's values, and r === x. Otherwise x is not fully updated (a value is left unchanged) and only r holds y's values.

Fallback: false for any type without its own method. Mutable arrays are true, other arrays false; a Tuple or NamedTuple is true when every element is; a ManifoldVar is true when its point is. The result is a compile-time constant.

A custom type with an in-place update! must define copyvars, syncvars! and ismutablevar(::Type{<:MyType}) = true.

Example

julia> ismutablevar([1.0, 2.0]), ismutablevar(SVector(1.0, 2.0)), ismutablevar(MVector(1.0, 2.0))
(true, false, true)

julia> ismutablevar(([1.0], [2.0])), ismutablevar(([1.0], SVector(2.0)))
(true, false)

julia> ismutablevar(Ref(1.0))   # mutable, but not a variable type that has opted in
false

Traits

OptimizationVariableInterface.isbitsvartype — Function
isbitsvartype(T) -> Bool

Returns true if T is an isbitstype DataType or a Union of isbitstype types. copyvars and syncvars! read it on a Vector{T} of variables: when it is true the elements are values, and the vector is copied in one go; otherwise each element is copied or synced with copyvars or syncvars!.

Example

julia> isbitsvartype(SVector{3, Float64}), isbitsvartype(Union{Float64, Int}), isbitsvartype(Vector{Float64})
(true, true, false)
source
OptimizationVariableInterface.iseliminable — Function
iseliminable(::Type{V}) -> StaticBool

Returns static(true) if variable type V is structurally eligible for Schur complement elimination (marginalization in bipartite problems such as bundle adjustment). Read by optimizers that eliminate variables, such as NLLSModel. iseliminable(x) is iseliminable(typeof(x)).

Fallback: static(false). A custom type opts in by defining OptimizationVariableInterface.iseliminable(::Type{<:MyType}) = static(true).

Example

julia> struct Point3D; x::SVector{3, Float64}; end

julia> OptimizationVariableInterface.iseliminable(::Type{<:Point3D}) = static(true)

julia> iseliminable(Point3D(SVector(0.0, 0.0, 0.0))), iseliminable(1.0)
(static(true), static(false))

OptimizationVariableInterface.ZeroToInfScalar — Type
ZeroToInfScalar(val)

Positive scalar variable parameterized on (0, Inf) via multiplicative exponential retraction. The state is stored as logval = log(val), so retraction is one exact addition; val = exp(logval) is cached (clamped to [floatmin, floatmax]). A step s multiplies the value by exp(s). The constructor takes the value; ZeroToInfScalar(z, Val(:log)) takes the state. NaN propagates.

Example

julia> x = ZeroToInfScalar(2.0);

julia> x.val
2.0

julia> update(x, [log(3.0)]).val
6.0
source
OptimizationVariableInterface.ZeroToOneScalar — Type
ZeroToOneScalar(val)

Bounded scalar variable parameterized on the open interval (0, 1) via logistic retraction (logit(p') = logit(p) + step). The state is stored as logit; val = p and comp = 1 - p are cached and computed without cancellation, so both are accurate near either end. The constructor takes the value (clamped to the open interval); ZeroToOneScalar(z, Val(:logit)) takes the state. NaN propagates.

Example

julia> w = update(ZeroToOneScalar(0.5), [40.0]);

julia> w.val, w.comp   # comp = 1 - val, accurate where val rounds to 1
(1.0, 4.248354255291589e-18)

julia> update(w, [-40.0]).val   # the state is exact, so the step is undone
0.5
source
OptimizationVariableInterface.BoundedReal — Type
BoundedReal(val, lo, hi)

Scalar variable bounded to the open interval (lo, hi) (finite lo < hi), using the same logit state as ZeroToOneScalar: val = lo + (hi - lo)·p with p = logistic(logit). val is cached and measured from the nearer bound, so it is accurate near both ends. The bounds lo and hi are fields (never optimized, copied unchanged by update).

However large the step, the state stays finite and val never leaves [lo, hi]. In exact arithmetic the bounds are never reached; in floating point val rounds to a bound once the distance to it is below its spacing, while distlo and disthi stay positive and accurate. The derivative of val with respect to the step is (hi - lo)·p(1 - p), so an optimum on a bound is approached slowly rather than becoming active.

The constructor takes the value, clamped to the open interval, and throws an ArgumentError unless lo and hi are finite with lo < hi; BoundedReal(z, lo, hi, Val(:logit)) takes the state. NaN propagates.

Example

julia> r = BoundedReal(2.0, 1.0, 5.0);

julia> r.val, distlo(r), disthi(r)
(2.0, 1.0, 3.0)

julia> r2 = update(r, [100.0]);

julia> r2.val, disthi(r2)   # val has rounded to hi; the distance has not
(5.0, 4.464091171224992e-43)
source
OptimizationVariableInterface.BoundedVector — Type
BoundedVector(val, lo, hi)

Vector variable with per-component open bounds (lo[i], hi[i]): the vector analogue of BoundedReal. val is any AbstractVector (e.g. SVector, Vector, MVector) and is used as the storage type for the logit state and the cached values; lo and hi are vectors of the same length or scalars applied to every component, and are stored in the same kind of container as val. Bounds are never optimized and are shared (not copied) by update, which is out-of-place. For a StaticVector, nvars is static.

Values are clamped to the open intervals, NaN propagates, and an ArgumentError is thrown unless every bound is finite with lo[i] < hi[i]. BoundedVector(z, lo, hi, Val(:logit)) takes the state. A BoundedVector forwards indexing, iteration, reductions, broadcasting and arithmetic to its cached val, and dot, cross, norm and normalize when LinearAlgebra is loaded.

Example

julia> bv = BoundedVector(SVector(0.2, 3.0), [0.0, 1.0], [1.0, 5.0]);

julia> nvars(bv)
static(2)

julia> bv[2]
3.0
source
OptimizationVariableInterface.distlo — Function
distlo(v::BoundedReal)

Distance from the value of v to its lower bound, v.val - v.lo, computed from the logit (one exp) so that it is accurate, and positive, even where v.val has rounded to the bound. See also disthi.

Example

julia> distlo(BoundedReal(2.0, 1.0, 5.0))
1.0
source
OptimizationVariableInterface.disthi — Function
disthi(v::BoundedReal)

Distance from the value of v to its upper bound, v.hi - v.val, computed from the logit (one exp) so that it is accurate, and positive, even where v.val has rounded to the bound. See also distlo.

Example

julia> disthi(BoundedReal(2.0, 1.0, 5.0))
3.0

Manifolds

Methods for these are defined when ManifoldsBase is loaded; see ManifoldsBase integration.

OptimizationVariableInterface.ManifoldVar — Type
ManifoldVar(point, context)

Variable wrapper for a point on a manifold, with its context: a ManifoldContext (by value) or a Base.RefValue of one (by reference), as returned by manifoldcontext. Variables can share a context.

When ManifoldsBase is loaded, ManifoldVar(point, manifold; basis=..., retraction=..., byref=...) builds the context too, with the default retraction for the type of point, and the methods of the interface are defined: nvars is the manifold dimension, always a StaticInt; update retracts the point along the tangent vector with coordinates step[start:start+nvars-1] in the context's basis; update!, copyvars and syncvars! work in place when the point is a mutable array, and ismutablevar(v) == ismutablevar(v.point).

Example

julia> v = ManifoldVar(SVector(1.0, 0.0, 0.0), ManifoldsBase.DefaultManifold(3; parameter = :type));

julia> nvars(v)
static(3)

julia> update(v, [0.1, 0.2, -0.1]).point
3-element SVector{3, Float64} with indices SOneTo(3):
  1.1
  0.2
 -0.1
source
OptimizationVariableInterface.ManifoldContext — Type
ManifoldContext(manifold, basis, retraction, dim)

Bundles a manifold, tangent basis, retraction method and the manifold dimension dim (a StaticInt, so that nvars of a manifold variable is always static) for a manifold variable. When ManifoldsBase is loaded, ManifoldContext(manifold, basis, retraction) computes dim itself, and ManifoldContext(manifold; basis=..., retraction=..., pointtype=...) fills in defaults. Both always return a ManifoldContext; use manifoldcontext to choose between by-value and by-reference storage. The default basis is DefaultOrthonormalBasis(), and the default retraction is default_retraction_method(manifold, pointtype) if pointtype is given, otherwise default_retraction_method(manifold).

Example

julia> ctx = ManifoldContext(ManifoldsBase.DefaultManifold(3));

julia> ctx.dim
static(3)
source
OptimizationVariableInterface.manifoldcontext — Function
manifoldcontext(manifold; basis=..., retraction=..., pointtype=nothing, byref=nothing)

Factory for a context to share between manifold variables. Builds ctx = ManifoldContext(manifold; basis, retraction, pointtype) (see ManifoldContext for the defaults), and returns ctx itself, stored by value, or Ref(ctx), a Base.RefValue{<:ManifoldContext} for by-reference storage. With byref = nothing (the default), by-reference is chosen when the context is not isbits or is larger than 16 bytes; byref = true or false forces the choice.

Defined in the ManifoldsBase extension: it has methods only once ManifoldsBase is loaded.

Example

julia> M = ManifoldsBase.DefaultManifold(3; parameter = :type);   # a 0-byte manifold

julia> manifoldcontext(M) isa ManifoldContext
true

julia> manifoldcontext(M; byref = true) isa Base.RefValue{<:ManifoldContext}
true
