OptimizationVariableInterface.jl

A lightweight, zero-overhead variable and retraction interface for numerical and nonlinear optimization in Julia.

In nonlinear optimization, the variables often do not live in a flat Euclidean space $\mathbb{R}^n$. They may be points on a manifold (rotations, poses, directions on a sphere) or parameters confined to an interval or to the positive reals. Moving such a variable along a search direction is not vector addition $x + \Delta x$: the optimizer computes a step $\Delta x$ in the tangent space $T_x\mathcal{M} \cong \mathbb{R}^d$ and maps it back onto the variable's domain with a retraction, $x_{k+1} = \mathcal{R}_x(\Delta x)$.

OptimizationVariableInterface.jl is the contract between variable representations and optimization algorithms. An optimizer works only with flat tangent vectors, sized by nvars and applied by update or update!, so it needs no knowledge of the variables' geometry. The interface supports compile-time static sizes (Static.jl, StaticArrays.jl), allocation-free scratch buffers, mutable and immutable variables alike, and heterogeneous collections of variable blocks treated as one state.

Installation

using Pkg
Pkg.add("OptimizationVariableInterface")

A first variable type

An angle on the circle $S^1$ has one degree of freedom, and wraps modulo $2\pi$. Two methods make it a variable:

using OptimizationVariableInterface, Static
import OptimizationVariableInterface: nvars, update

struct CircleAngle{T<:AbstractFloat}
    theta::T
end

nvars(::CircleAngle) = static(1)
update(var::CircleAngle, step, start=1) = CircleAngle(mod2pi(var.theta + step[start]))

angle = CircleAngle(0.0)
nvars(angle)
static(1)
update(angle, [pi])   # retract by a tangent step of π radians
Main.CircleAngle{Float64}(3.141592653589793)

Any optimizer written against the interface can now optimize a CircleAngle, alone or as one block of a larger state.

Who uses it

SecondOrderOptimization.jl (Newton, Levenberg–Marquardt, dogleg and gradient-descent optimizers) and NLLSModel.jl (nonlinear least-squares problems) are built on this interface: any variable type that implements it can be optimized by them.
