Bounded types

The bounded types store an unconstrained state, the logarithm or the logit of the value, and cache the value derived from it. A retraction is one exact addition to the state, so the result can never leave the interval, however large the step, and a step followed by its negative returns exactly to the start.

ZeroToInfScalar: positive scalars

ZeroToInfScalar is a positive scalar. Its state is logval = log(val), and a step $s$ multiplies the value by $e^s$. Read the value from val:

x = ZeroToInfScalar(2.0)
x.val, update(x, [log(3.0)]).val
(2.0, 6.0)

The cached value is clamped to [floatmin, floatmax], so it stays positive and finite after any step:

update(x, [-1000.0]).val, update(x, [1000.0]).val
(2.2250738585072014e-308, 1.7976931348623157e308)

ZeroToOneScalar: the unit interval

ZeroToOneScalar is on the open interval $(0, 1)$. Its state is the logit, $\log(p / (1 - p))$; the value val = p and its complement comp = 1 - p are both cached, each computed without cancellation, so comp stays accurate where val has rounded to 1:

w = ZeroToOneScalar(0.5)
w2 = update(w, [40.0])
w2.val, w2.comp
(1.0, 4.248354255291589e-18)
update(w2, [-40.0]).val   # back exactly
0.5

BoundedReal: an interval

BoundedReal is on $(lo, hi)$, for finite $lo < hi$, with the same logit state as ZeroToOneScalar: $val = lo + (hi - lo)\,p$. The bounds are fields, not type parameters, so they can be set at run time; they are never optimized, and update copies them unchanged. distlo and disthi give the distance to each bound, computed from the logit so that they are accurate near it:

r = BoundedReal(2.0, 1.0, 5.0)
r.val, distlo(r), disthi(r)
(2.0, 1.0, 3.0)
r2 = update(r, [0.3])
1.0 < r2.val < 5.0
true

BoundedVector: per-component bounds

BoundedVector is the vector analogue of BoundedReal, with bounds lo[i] < hi[i] for each component; a scalar bound applies to every component. The value can be any AbstractVector (an SVector, Vector, MVector, ...), and its type is the storage type for the state, the cached values and the bounds. With static storage, nvars is static:

bv = BoundedVector(SVector(0.2, 3.0), [0.0, 1.0], [1.0, 5.0])   # static storage
nvars(bv)
static(2)
bd = BoundedVector([0.2, 3.0], 0.0, 5.0)   # Vector storage, scalar bounds
nvars(bd)
2
update(bv, SVector(0.1, -0.1)).val
2-element StaticArraysCore.SVector{2, Float64} with indices SOneTo(2):
 0.21648068905247012
 2.90008325008424

update is out of place and shares lo and hi with the original.

Construction, bounds and NaN

  • Construction always takes a value, including the parameterized forms (ZeroToInfScalar{Float32}(2.0), BoundedReal{Float64, Float64}(v, lo, hi)). The raw state is reachable only through the tagged forms, ZeroToInfScalar(z, Val(:log)), ZeroToOneScalar(z, Val(:logit)), BoundedReal(z, lo, hi, Val(:logit)) and BoundedVector(z, lo, hi, Val(:logit)), and is read back from the logval or logit field.

  • The constructors clamp the value to the open interval, so a value on a bound gives a finite state:

    BoundedReal(1.0, 1.0, 5.0).logit
    -37.42994775023704

  • NaN propagates rather than being masked:

    ZeroToOneScalar(NaN).val, update(BoundedReal(2.0, 1.0, 5.0), [NaN]).val
    (NaN, NaN)

  • Invalid bounds are an ArgumentError:

    try
    BoundedReal(2.0, 5.0, 1.0)
catch err
    sprint(showerror, err)
end
    "ArgumentError: need finite lo < hi, got (5.0, 1.0)"

  • In exact arithmetic the bounds are never reached. In floating point, val rounds to a bound once the distance to it is below the spacing of floating-point numbers there; the state, comp, distlo and disthi stay accurate:

    r3 = update(r, [100.0])
r3.val, disthi(r3)
    (5.0, 4.464091171224992e-43)

  • The derivative of val with respect to the step is $(hi - lo)\,p(1-p)$, which vanishes at the bounds: an optimum on a bound is approached slowly, rather than becoming an active constraint.

  • update works with automatic differentiation: with a ForwardDiff.Dual step, the state and cached values become duals while the bounds stay plain numbers.

Operator forwarding

ZeroToInfScalar, ZeroToOneScalar, BoundedReal and BoundedVector forward the standard arithmetic, comparison and mathematical functions (+, -, *, /, ^, sin, exp, <, ==, ≈, ...) to their cached val, so they can be used directly in residual code. The result is a plain number or vector, not a wrapper:

w = ZeroToOneScalar(0.25)
2w, sin(w), w < 0.5
(0.5, 0.24740395925452294, true)

== and < compare val only. BoundedVector also forwards indexing, iteration, reductions and broadcasting:

bv[1], sum(bv), sqrt.(bv)
(0.2, 3.2, [0.4472135954999579, 1.7320508075688772])

When LinearAlgebra is loaded, the package extension OVILinearAlgebraExt forwards dot, cross, norm and normalize too:

norm(bv), dot(bv, [1.0, 1.0])
(3.0066592756745814, 3.2)
